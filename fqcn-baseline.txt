# fqcn-baseline.txt — the ratchet behind `checkNoFqcn`.
#
# The house rule is "no FQCN except collisions" (docs/contributors/code-as-art.md, House rules ->
# Java 25). It was never enforced: `jk format`'s `optimize-imports` pass built its OpenRewrite
# parser with no classpath, so it resolved nothing and shortened nothing, and twelve module audits
# each filed the same finding independently. One pass threaded the classpath in; the next swept the
# tree. 4,306 package-qualified references across 622 files became 878 across 253, and the
# round-3 owner sweeps took it to 598 across 135 — the count below, which the guard prints
# whenever a listed file shrinks. Retighten from that printout; never retype it.
#
# What a package-qualified reference is, for counting: two or more all-lowercase dot-separated
# segments followed by an UpperCamel identifier, in code — comments, string literals and the file's
# own `import`/`package` lines do not count. Recount one file by deleting its entry and running
# `./gradlew :<module>:checkNoFqcn`; the failure prints the number.
#
# The three rules `checkNoFqcn` enforces against this list:
#
#   1. A listed file may only shrink. Gaining a reference fails the build.
#   2. A file that is NOT listed must have zero. Adding it here instead is the escape hatch, and
#      it is a reviewable diff.
#   3. Every entry sits under a `## <reason>` section that says why the reference survives, and an
#      entry under `## collisions` names the collision on the line directly above it.
#
# A file is filed under its most specific reason; a file whose residue has two causes appears once.
#
# UPDATING AFTER A SHRINK. Shrinking a listed file passes — the ratchet never blocks progress. The
# guard prints the tightened line, e.g.
#
#     fqcn-baseline.txt is loose (these shrank — tighten it in this commit):
#           12  server/engine/src/main/java/cc/jumpkick/runtime/TrainRunner.java   (was 24)
#
# Paste that number over the old one. Deleting a listed file works the same way: drop its entry.
#
# FORMAT. One entry per line: `<count>  <path from the repo root>`, sorted by path within a section.

## unreachable-by-the-formatter
# 111 of the tree's 2,088 Java files fail OpenRewrite's own print-idempotence check: its Javadoc
# printer mangles the continuation line of a wrapped `@param` (it eats one space of indent and
# duplicates the trailing characters), so `JavaParser` returns a ParseError rather than a
# compilation unit and the whole file is skipped. The check is right to exist — the alternative is
# writing the mangled print back over the source — so until rewrite-java fixes the printer these
# files cannot be shortened by `jk format` at all, and every reference in them survives. They are
# still Spotless-formatted; only the OpenRewrite pass is skipped, and `jk format --check` does not
# fail on one: it is OpenRewrite's defect, not the author's, and no edit to the file clears it.
#
# These are the 56 of those 111 that carry a reference. `jk format` will shrink them for free on
# the day the printer is fixed; nothing else will.
#
# THIS SECTION IS MEASURED, NOT CURATED. `jk format` used to report a file it
# could not parse as already clean — a skipped pass and "nothing to shorten" were the same answer —
# so the only way to know which files these were was to run the parser by hand, and the list here
# was typed. `jk format` now reports them, and regenerating this section is two commands:
#
#     jk format                                                    # settle the formatting first
#     NO_COLOR=1 jk format --check | sed -n 's/^! unparseable: //p' | sort > /tmp/unreachable
#
# The apply run is not optional: a file that is both unformatted AND unparseable reports as
# `unformatted`, because --check still has to fail on it. Then delete this section's entries, run
# `./gradlew checkNoFqcn --continue`, and every file it names as "not in fqcn-baseline.txt" that is
# also in /tmp/unreachable belongs here, with the count the guard printed. The counts come from the
# guard and never from a second implementation of the counting rule. A file the guard does not name
# has no reference left and simply drops out — which is how this section shrinks by itself as
# OpenRewrite's printer improves, instead of ossifying into an exemption nobody revisits.

## outside-the-recipe
# Three kinds of reference `ShortenFullyQualifiedTypeReferences` does not rewrite, in files it
# otherwise swept clean:
#
#   * A static member or a qualified static call. The recipe rewrites a `J.FieldAccess` only when
#     the access itself resolves to a top-level class, so `java.lang.foreign.ValueLayout.JAVA_INT`
#     and `cc.jumpkick.host.Hashing.sha256Hex(x)` are left alone. Both are a two-line hand edit
#     (add the import, drop the package) and `jk format` will never undo one.
#   * An annotation type — `@org.jspecify.annotations.NullMarked` on a package-info, and a handful
#     of `@org.junit.jupiter.api.*` in tests.
#   * A third-party type. The lock's 150 dependency jars measured at 4.6x the format time
#     (8m14s vs 2m07s) for 1.4% more shortenings, and they crashed the worker JVM in 2 of 4 runs,
#     so they are deliberately off the format classpath and their types cannot be resolved.
#
# One more, worth knowing before adding to this list: an unresolvable simple name in a Javadoc
# `{@link}` — `{@link #converse(List, Map, ...)}` with no `import java.util.Map` — makes the recipe
# decline to shorten that type anywhere in the file. Fixing the link fixes the shortening.
