# Guard letters that are deliberately NOT enforced by both builds, and why.
#
# `./gradlew build` and `jk build` are meant to enforce the same house rules
# (docs/contributors/code-as-art.md). Five letters drifted to the Gradle side and stayed there,
# so the self-hosted build — the one contributors actually run — reported the rules green while
# enforcing fewer of them. This file is the exception list for the parity check that stops that
# happening again (G51, checked from both sides).
#
# One letter per line: `G<n> <reason>`. An entry is a claim that the letter CANNOT sensibly live
# in both, not that nobody got around to it. "Not ported yet" is not a reason — port it.

# Implemented as a test in one module, which both builds run as part of that module's suite. The
# charter's rule is that a guard scoped to ONE module belongs beside the suite it governs: as a
# test it gets assertions, a debugger and a failure report instead of script.
G32 guard test `spike-cache-temp-dir` (server/engine/src/guard) — the Gradle build does not run the guard suite

# Reads Gradle's own publication model.
G19 checkPublishedPomCoordinates reads build/publications/*/pom-default.xml, which Maven-publish
G19 generates and jk's publisher does not produce. Settled: Gradle is the only publisher that can
G19 emit `unspecified` or a fallback group — jk's PublishablePom takes group, name and version from
G19 the manifest, where a publishable project must declare all three concretely or fail to parse,
G19 so the defect this letter bans has no way to occur on the jk side. Permanent, not deferred.

# Folded / never allocated — no code behind the letter on either side.
G4 guard test `cli-no-parse-types` (clients/cli/src/guard) here; folded into :cli's checkCliNoParseTypes on the Gradle side, which has no letter of its own
G41 never allocated and not reusable

# Self-hosted-build only: these are about the relationship BETWEEN the two builds, or about the
# gate's own integrity, so a Gradle twin would either be circular or meaningless.
G0 checkCorpus is the floor under every other guard in this file — it fails when the gate's own
G0 corpus shrinks below the population the scans were measured against. It guards this file, so
G0 it lives with this file.
G44 checkBothBuildsSeeEveryModule compares settings.gradle.kts against the root jk.toml
G44 [workspace]. Asking Gradle to check that both builds see every module makes Gradle the
G44 authority on a question about Gradle; the self-hosted side is the honest place for it.

# A property of the Gradle task graph, not of the sources: whether a JavaCompile task is enabled.
# The self-hosted build has no task to disable, and the hole it closes only exists on the Gradle side.
G64 checkNoDisabledCompile — Gradle task-graph state; the jk build has no compile task to disable

# 2026-09-06 — letters that have moved into jk-guards.toml (Guards.kt `ruleId`) are enforced on the
# jk side by the guard engine and on the Gradle side by their original task. Parity now means "the
# letter is enforced by both builds", not "the same code runs". Gradle running jk-guards.toml itself
# (a JavaExec over server/guard) is the owner's follow-up; until then the Gradle twins stay.

# one signature list and one args set, so an arm with its own shape is its own rule and its own
# letter on the jk side; the Gradle twin of the parent letter enforces the same check unsplit.

G68 checkSingleXmlParserOwner still checks them inside G3. 2026-09-06.

G69 Gradle's checkOneDigestSurface still checks it inside G6. 2026-09-06.
G70 central-address is G16's URL and alias-host arm (text, not a vocabulary the owner declares);
G70 Gradle's checkSingleCentralAddress still checks it inside G16. 2026-09-06.
G71 spa-no-class-key is G28's SPA-only arm (a different file set than the retired keys);
G71 Gradle's checkNoRetiredWireSpelling still checks it inside G28. 2026-09-06.
G72 checkCharterTableParity compares docs/contributors/code-as-art.md against jk-guards.toml's
G72 file-size caps and against its own headings: a question about this repository's charter and
G72 this gate, with nothing for a Gradle twin to enforce. Split from G10 when G10 became the
G72 file-size metric rule. 2026-09-06.
G75 ship-layout-installer-jk is G62's installer-vs-jk-dist pair as a `parity` rule; Gradle's
G75 checkShipLayoutAgrees still compares all three anchors inside G62. 2026-09-07.
G76 guard-registry-doc renders jk-guards.toml's own registry into code-as-art.md — a `generated`
